# План тестирования — ЛР №9

## 1. Объект тестирования

**Система учёта заявок** — учебный проект по дисциплине «Технологии разработки программного обеспечения».

- **Версия**: коммит `0eb9fbd` (ветка `main`)
- **Дата тестирования**: 2026-11-14
- **Тестовая среда**: удалённое приложение на Render
  - Swagger UI: https://chernousov-oleg-eozisip303.onrender.com/docs
  - Health-check: https://chernousov-oleg-eozisip303.onrender.com/health
  - API: https://chernousov-oleg-eozisip303.onrender.com/api/requests
- **Браузер**: Chrome (последняя версия), ОС Windows 11
- **Инструменты**: Swagger UI, curl (Git Bash), браузер

## 2. Что проверяется

- Создание, просмотр, редактирование, удаление заявок
- Смена статуса, назначение исполнителя
- Добавление комментариев
- Поиск и фильтрация
- Валидация входных данных (обязательные поля, несуществующие FK)
- Корректность HTTP-кодов (200, 201, 204, 404, 422)
- Согласованность данных: создание через API → чтение → данные сохранены
- Справочники (пользователи, категории, статусы)
- Health-check

## 3. Что не входит в проверку

- Нагрузочное тестирование (не требуется по методичке)
- Тестирование безопасности (аутентификация/авторизация не реализованы в проекте)
- Тестирование UI (веб-интерфейс не реализован, сценарии проверяются через API/Swagger)
- Мобильная версия
- Тестирование на реальных персональных данных (используются только тестовые данные из seed.sql)

## 4. Виды тестов

- **Функциональные позитивные** — основные сценарии работают
- **Негативные** — невалидные данные, несуществующие ID
- **Граничные** — пустые строки, максимальная длина, специальные символы
- **Интеграционные** — API + БД (создание → чтение → данные сохранены)
- **API** — HTTP-коды, формат ответов, обработка ошибок

## 5. Критерии начала

- Приложение доступно по адресу Render (`/health` → `{"status":"ok"}`)
- БД создана и наполнена тестовыми данными (5 заявок, 5 пользователей, 4 категории, 4 статуса)
- Swagger UI открывается

## 6. Критерии завершения

- Все 20+ тест-кейсов выполнены, у каждого есть фактический результат и статус PASS/FAIL/BLOCKED
- Все применимые категории сценариев представлены
- Найденные дефекты (если есть) задокументированы с доказательствами
- AI-журнал заполнен (2 взаимодействия)
- Скриншоты/логи приложены
